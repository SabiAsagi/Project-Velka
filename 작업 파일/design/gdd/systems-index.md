## 구현 코드와의 대략적인 대응

이 인덱스는 설계 문서만 다루지만, 참고용으로 구현 코드 위치도 함께 남깁니다 (정식 추적은 아님):

| 시스템 | 코드 위치 |
|---|---|
| 캐릭터/파티 | `scripts/characters/` (Player, PartyMember, PlayerPartyManager, CompanionAI) |
| 학교 맵 | `scenes/school/`, `scripts/school/` (Phase1Validate.gd, Phase2Validate.gd), `data/school/` |
| 대화 시스템 | `scripts/ui/DialogueBox.gd`, `data/dialogues/` |
| 규칙서 데이터 | `data/rules/school_rules.json` |
| 테스트 러너 | `debug/TestRunner.gd` |

## 알려진 한계

- 이 인덱스의 "상태(비공식)" 열은 파일 최근 수정 이력과 파일명만으로 추정한 값이며,
  각 문서를 정독하여 검증한 값이 아닙니다. 실제 상태를 알려면 해당 문서를 열어 확인하세요.
- 이 인덱스는 `/gate-check`, `/create-stories`, `/architecture-review` 등 템플릿 스킬이
  자동으로 신뢰할 수 있는 정식 `systems-index.md`가 아닙니다. 그 스킬들을 온전히 쓰려면
  `docs/adoption-plan-2026-09-23.md`의 "전체 마이그레이션" 또는 "하이브리드 포인터 파일"
  전략으로 전환해야 합니다.

## 갱신 방법

`docs/01~05` 아래 새 문서가 추가되거나 기존 문서의 범위가 바뀌면 이 표에 행을 추가/수정하세요.
새로운 메커닉을 처음부터 템플릿 GDD 형식(`design/gdd/[system].md`, 8개 필수 섹션)으로 작성하기로
결정했다면, 해당 행에 두 번째 원본 경로로 새 GDD 파일을 추가하세요.
