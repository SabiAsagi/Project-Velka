# 프로젝트 벨카 — Godot 학교 맵 Codex 구현 가이드

> 목적: Codex가 `학교_맵_상세.md`와 `00_전체_배치.png`~`11_강당_2F.png`를 자의적으로 재해석하지 않고, **최종 구조를 정확하게 Godot 3D 맵으로 구현하도록 통제하는 작업 명세**다.

> **개정 이력**: 이전 Phase 0 감사에서 나온 `TODO_CONFIRM-001`~`TODO_CONFIRM-008`을 모두 이번 개정에서 해결했다. 문서명 표기(`학교_맵_상세.md`), 실제 픽셀 크기, 별관 방향·라벨 규칙, 스탠드·자습실 확정값, 외부 보행로 범위, 월드 원점을 본문에 반영했다. 세부 내용은 각 항목이 언급된 절의 `TODO_CONFIRM-00N 해결` 표기를 참고한다.

## 1. 가장 중요한 원칙

Codex는 이 작업에서 **맵 디자이너가 아니라 구현 담당자**다.

따라서 아래 행동을 금지한다.

- 구조를 더 현실적으로 보이게 하려고 임의로 방을 추가·삭제하는 행위
- 계단, 엘리베이터, 구름다리, 문 위치를 재배치하는 행위
- 레퍼런스에 없는 연결 통로를 만드는 행위
- 복도 폭과 방 크기를 임의로 축소하는 행위
- Markdown에 적힌 과거 구조를 최종 이미지보다 우선하는 행위
- 처음부터 고품질 모델링, 재질, 조명, NPC, 괴이 연출을 동시에 구현하는 행위
- 전체 맵을 한 번에 생성한 뒤 결과만 보여주는 방식

불명확한 부분은 추측하지 말고 `TODO_CONFIRM`으로 남긴다.


## 1-1. 실행 계약 — 반드시 지켜야 하는 작업 방식

이 문서의 문장은 권장사항이 아니라 **구현 승인 조건**이다. Codex는 작업을 시작할 때 현재 Phase와 허용 작업을 먼저 선언하고, 해당 Phase 이외의 파일과 기능을 수정하지 않는다.

- 한 번의 작업 요청에서는 **지정된 Phase 하나만** 수행한다.
- Phase 완료 후 다음 단계로 넘어가지 않고 반드시 멈춘다.
- 완료 보고 마지막 줄에 `PHASE_COMPLETE_WAITING_APPROVAL`을 출력한다.
- 사용자 승인 문구가 없으면 다음 Phase를 시작하지 않는다.
- 레퍼런스와 다른 구조를 발견해도 스스로 고치거나 재설계하지 않는다.
- 방, 문, 계단, 엘리베이터, 길, 화단, 스탠드, 조회대의 추가·삭제·이동은 모두 금지한다.
- 구현 편의를 이유로 구조를 단순화하거나 좌우 대칭으로 다시 만드는 것도 금지한다.
- “비슷하게”, “현실적으로”, “게임플레이에 맞게”라는 이유로 레퍼런스를 변형하지 않는다.
- 불확실한 항목은 구현하지 않고 `TODO_CONFIRM`에 좌표·대상·이유를 기록한다.

## 1-2. 실패 시 즉시 중단 조건

아래 중 하나가 발생하면 계속 구현하지 말고 해당 Phase를 실패로 보고한다.

- 필수 레퍼런스 파일을 하나라도 열지 못함
- 이미지의 방향을 확정하지 못함
- 방 순서나 연결 층이 문서와 다름
- 레퍼런스에 없는 통로·문·계단이 생성됨
- 정사영 비교에서 외곽선이 기준선보다 `0.5m` 이상 어긋남
- 지정된 씬이 아닌 다른 씬까지 수정함
- 자동 생성 코드가 기존 구조를 덮어쓰거나 재배치함

실패 시 결과를 억지로 완성하지 말고 `BLOCKED_REFERENCE_MISMATCH`와 함께 차이만 보고한다.

## 3-1. 방향 적용 규칙

- 전체 배치와 본관 이미지는 보이는 방향 그대로 사용한다.
- 별관 평면 이미지는 읽기 쉽도록 가로로 그려져 있다. 전체 부지에서는 긴 축이 남북 방향이므로 **화면 기준 90° 반시계 방향으로 돌린 상태**와 동일하게 배치한다.
  - 별관 이미지의 오른쪽 끝은 실제 북측 끝이다.
  - 별관 이미지의 왼쪽 끝은 실제 남측 끝이다.
  - 별관 이미지의 아래쪽 긴 외벽은 실제 운동장을 향한 동측 입면이다.
  - `09_별관_3F.png` 오른쪽 끝의 구름다리는 실제 북측 끝에서 본관으로 연결된다.
- **별관은 본관처럼 정면(남측)을 바라보고 그대로 배치되는 건물이 아니다.** 본관은 이미지를 회전하지 않고 그대로 배치하지만, 별관은 위 규칙대로 항상 90° 반시계 회전한 상태로 배치해야 하며, 이 회전을 생략하고 이미지 그대로 좌=서/우=동으로 두면 전체 배치와 어긋난다.
- **별관 이미지 내부에 그려진 텍스트 라벨의 서측/동측 표현은 회전 전 원본 기준이며, 회전 후 실제 방위와 다르다 (`TODO_CONFIRM-003`, `TODO_CONFIRM-004` 해결).**
  - `07_별관_1F.png`에 그려진 "서측 학생 주출입구" 라벨은 이미지 왼쪽(좌측 계단 쪽)에 있으므로, 회전 후에는 **실제 남측 끝** 출입구를 가리킨다.
  - 같은 이미지의 "동측 비상·반입구" 라벨은 이미지 오른쪽(우측 계단 쪽)에 있으므로, 회전 후에는 **실제 북측 끝** 출입구를 가리킨다.
  - 즉 별관 1층 운동장 방향(동측) 긴 입면의 출입구 2개 중, **남측 끝 = 학생 주출입구, 북측 끝 = 비상 출구 겸 급식 물품 반입구**로 확정한다. 실제 배치·코드·주석에는 "서측 문"/"동측 문" 대신 "남측 끝 출입구"/"북측 끝 출입구"라는 표현만 사용한다.
  - `학교_맵_상세.md`의 별관 층별 구성표가 3층 복도 끝 연결을 "동쪽 복도 끝 구름다리"로 표기한 것도 같은 회전 전 원본 기준 표현이다. PNG와 위 회전 규칙에 따라 실제 위치는 **북측 끝**이며, 이 문서(구현 가이드)가 우선 적용된다. `학교_맵_상세.md`의 "동쪽" 표기와 실제 좌표가 다른 지점을 가리키는 것이 아니라, 단순히 서로 다른 기준(원본 프레임 vs 실제 방위)을 쓴 것뿐이므로 구조 충돌이 아니다.
- 강당 이미지는 북측 주출입구가 이미지 아래쪽에 있다. **동·서를 바꾸지 말고**, 이미지 아래를 북측, 위를 남측으로 해석한다.
- 파일 번호만 보고 자동 회전하지 않는다. 위 표의 가장자리 방향을 `layout_manifest.json`에 명시한다.

# 4. 정본 관계와 충돌 처리

현재 사용하는 `학교_맵_상세.md`는 이번 12장 레퍼런스에 맞춰 갱신된 현행 상세 문서다. 따라서 과거 가이드에 있던 “상세 문서가 이전 구조다”라는 전제는 사용하지 않는다.

## 4-1. 역할 분담

| 자료 | 결정하는 내용 |
| --- | --- |
| 12장 PNG | 외곽선, 방향, 방 순서, 문·계단·엘리베이터 위치, 가구의 상대 배치, 길·주차장·스탠드·조회대 위치 |
| `학교_맵_상세.md` | 수치, 공간 용도, 좌석 수, 통로 폭, 층간 높이, 기믹, 상호작용, 변질 조건 |
| 이 구현 가이드 | 씬 분리, 제작 순서, 검증 방법, 금지사항, 보고 형식 |

## 4-2. 충돌 판정 순서

1. **형태와 위치가 다르면 PNG를 따른다.**
2. PNG에 수치가 없고 상세 문서에 수치가 있으면 상세 문서를 따른다.
3. PNG가 개념적으로만 표시한 높이·충돌·NPC 규칙은 이 가이드와 상세 문서를 따른다.
4. 서로 동시에 만족할 수 없으면 임의로 절충하지 말고 `TODO_CONFIRM`으로 중단한다.
5. 과거 구현, 과거 커밋, 자동 배치 스크립트는 정본이 아니다.

# 5. Godot 좌표계와 스케일

## 5-1. 기본 단위

- `1 Godot unit = 1m`
- 동쪽 = `+X`
- 서쪽 = `-X`
- 북쪽 = `-Z`
- 남쪽 = `+Z`
- 높이 = `+Y`
- 방향은 파일마다 다르므로 3절의 방향 표를 따른다. 이미지 위쪽을 일괄적으로 북쪽으로 가정하지 않는다.

### 5-1-1. 절대 원점 (World Origin)

Godot 월드 좌표 `(0, 0, 0)`은 **운동장 중앙점**으로 고정한다. 구체적으로는 운동장(`70m × 45m`) 중심선 교차점이며, 이는 조회대·본관 중앙 현관과 일직선으로 맞춰진 지점(6-3절 "조회대는 운동장 중앙선과 본관 중앙 현관의 축에 맞춘다" 참고)과 동일한 X축 위치다. 높이는 5-3절의 운동장 기준 지면과 동일하게 `Y = 0.0`으로 둔다.

- 모든 건물·시설·`ReferenceAnchor` 좌표는 이 원점을 기준으로 배치·기록한다.
- 원점은 `layout_manifest.json`의 `coordinate_system` 키에 명시적으로 기록하고, 임의로 다른 지점(예: 정문, 특정 건물 모서리)으로 바꾸지 않는다.
- 본관 중앙 현관 축은 원점을 지나는 Z축(남북) 선과 일치해야 하므로, 이 정렬이 어긋나면 전체 배치 오버레이 비교 실패로 처리한다 (`TODO_CONFIRM-008` 해결).

## 5-2. 스냅

- 건물 외벽·방 경계: `0.5m`
- 가구·소품: `0.25m`
- 기본 회전: `90°`
- 곡선 산책로·외부 경사면만 자유 각도 허용

## 5-3. 높이 기준

`학교_맵_상세.md`의 한 층 단차를 실제 연결 높이에 반영한다.

- 운동장·별관 1F·강당 1F·농구장 기준 지면: `Y = 0.0`
- 본관 1F 상부 대지: `Y = 3.8`
- 공통 층간 높이: `3.8m`
- 본관 B1 바닥: `Y = 0.0`
- 본관 1F 바닥: `Y = 3.8`
- 본관 2F 바닥: `Y = 7.6`
- 본관 3F 바닥: `Y = 11.4`
- 본관 4F 바닥: `Y = 15.2`
- 별관 1F 바닥: `Y = 0.0`
- 별관 2F 바닥: `Y = 3.8`
- 별관 3F 바닥: `Y = 7.6`
- 따라서 본관 2F와 별관 3F 구름다리 바닥은 둘 다 `Y = 7.6`
- 일반 문 높이: `2.1m`
- 일반 실내 유효 천장: `2.8~3.0m`
- 강당 유효 높이: `8~9m`
- 강당 2F 관람석 기준 바닥: 약 `Y = 4.0`

높이값은 전역 상수로 관리한다. 특정 층만 임의 조정해 구름다리를 비틀거나 경사 통로로 만들지 않는다.

# 5-4. 레퍼런스 오버레이 추적 방식 — 필수

Codex가 이미지의 비율을 눈대중으로 재해석하지 못하도록 각 씬에 임시 `ReferenceOverlay`를 둔다.

## 오버레이 구성

```text
Debug
└─ ReferenceOverlay
   ├─ ReferencePlane 또는 Sprite3D
   ├─ ReferenceBounds
   ├─ ReferenceAnchors
   └─ DebugTopCamera
```

- PNG를 바닥과 평행한 평면에 표시한다.
- 외곽 크기를 실제 미터 단위에 맞춘 뒤 잠금 처리한다.
- 오버레이는 충돌과 Navigation을 가지지 않는다.
- 구현 중 투명도 `35~50%`로 켜고 외벽·방 경계·문 중심선을 직접 추적한다.
- 완성 씬에서는 기본 비활성화하되 Debug 모드로 다시 켤 수 있게 남긴다.
- 외곽, 방 경계, 문 중심, 계단 중심에 `ReferenceAnchor`를 둔다.

## 추적 금지 방식

- 이미지 내용을 언어 모델이 요약한 뒤 요약만으로 자동 배치
- 방 개수를 맞추기 위해 동일 크기의 방을 균등 분할
- “대략 비슷한” 직사각형으로 건물을 재생성
- 좌우 대칭을 강제로 적용해 비대칭 요소 제거
- 하나의 절차 생성 스크립트로 모든 층을 같은 템플릿으로 덮어쓰기

## 오차 허용값

- 건물 외곽: `±0.25m`, 최대 `0.5m`
- 방 경계: `±0.25m`
- 문 중심: `±0.25m`
- 계단·엘리베이터 중심: `±0.25m`
- 외부 주요 시설: `±0.5m`
- 방 순서·연결 관계: 오차 허용 없음

오차를 맞추기 위해 다른 방을 밀거나 크기를 임의 축소하지 않는다. 충돌이 생기면 `TODO_CONFIRM`으로 보고한다.

### 본관 북측

- 본관 뒤편에 주차장이 존재한다.
- 주차장 중앙 북쪽에 후문 진입로가 이어진다.

- 주차장 북동측에 자전거 거치대를 둔다.
- 본관 양옆에 붙은 임의의 차량 도로나 보행로를 새로 만들지 않는다. `학교_맵_상세.md`의 통행·문·충돌 기준(외부 보행로)에 나오는 "본관 둘레" 표현은 본관을 완전히 감싸는 측면 보행로를 새로 만들라는 뜻이 아니라, 본관 앞(남측) 연속 3m 보행로·정문 진입부·운동장 순환로처럼 이미 존재가 확정된 구간들을 통칭한 것이다. `00_전체_배치.png`에 없는 본관 동·서 측면 보행로는 생성하지 않는다 (`TODO_CONFIRM-007` 해결).

### 본관 남측·스탠드

- 본관 남측에 좌·중앙·우 출입구 3개를 유지한다.
- 운동장 방향으로 `본관 → 화단·고목 → 3m 학생 보행로 → 화단·고목 → 스탠드 → 운동장` 순서를 유지한다.
- 출입구와 중앙 보행축 앞은 화단으로 막지 않는다.
- 본관 앞의 연속 `3m` 보행로를 유지한다.
- 스탠드는 본관 폭에 맞춰 길게 이어진다.
- 스탠드 양끝에만 상부 보행로로 오르는 계단이 있다.
- 스탠드 중앙은 계단이 아니라 **조회대**다.
- 조회대 아래에는 운동장 쪽으로 문이 난 창고가 있다.
- 조회대는 운동장 중앙선과 본관 중앙 현관의 축에 맞춘다.
- 조회대를 플레이어 이동 계단으로 사용하지 않는다.

### 서측

- 별관은 운동장 서측에 남북으로 길게 배치한다.
- 별관 서측 외곽에 휴게정원과 산책로가 있다.
- 산책로는 북측 별관 길과 남측 체육 구역 길에 모두 이어진다.
- 구름다리는 본관 2F에서 서쪽으로 나간 뒤 남쪽으로 꺾여 별관 3F 북측 끝에 닿는다.

### 동측

- 정문, 수위실, 시작 위치, 진입광장, 정문 정원, 원예부 재배화단을 이미지 위치에 맞춘다.
- 운동장 동측 `3m` 통로를 유지한다.
- 동측 통로와 본관 상부 보행로를 잇는 경사로를 유지한다.
- 체력단련장 아래쪽과 정문을 잇는 별도의 임의 도로는 만들지 않는다.
- 농구장과 화단 사이의 길을 삭제하지 않는다.

### 남측 체육 구역

- 강당은 운동장 남측 중앙에 둔다.
- 강당 북측 중앙 주출입구를 운동장 쪽으로 둔다.
- 강당 서·동측 출입구를 유지한다.
- 강당 남측에는 외부 출입구를 만들지 않는다.
- 강당 서·동측에 농구장 1면씩 둔다.
- 각 농구장 남측에 관람 스탠드와 화단·고목을 둔다.
- 최외곽 서·동측에 체력단련장을 둔다.
- 강당과 농구장 사이, 농구장과 체력단련장 사이의 보행로를 끊지 않는다.

# 9. 통로·충돌 기준

## 9-1. 최소 폭

| 구역 | 기준 |
| --- | ---: |
| 본관·별관 중앙 복도 | `3.0m` |
| 외부 주요 보행로 | `3.0m` |
| 교실·특별실 주통로 | `1.2m` |
| 책상 사이 보조 통로 | `0.9m` 이상 |
| 의자 뒤 이동 공간 | `0.9m` |
| 문 앞 대기 공간 | `1.5m` |
| 계단 앞 | `2m × 2m` |
| 엘리베이터 앞 | 깊이 `2m` |
| 구름다리 도착부 | `2m × 2m` |
| 급식실 중앙 통로 | `2m` |
| 급식실 배식·반납 앞 | `1.5m` |
| 강당 주출입 동선 | `3m` |
| 강당 동·서 출입 동선 | `2m` |
| 강당 2F 후면 통로 | `1.5m` |
| 막다른 통로 회전 공간 | 지름 `1.5m` |

"외부 주요 보행로"는 6-3절에서 확정한 구간(본관 앞 남측 3m 보행로, 별관 동측, 정문 진입부, 운동장 서·동·남측 순환로, 강당 연결부, 휴게정원 산책로 등)에만 적용한다. 본관 동·서 측면에는 보행로를 두지 않는다 (`TODO_CONFIRM-007`).

## 9-2. 문 규칙

- 복도 문은 열린 문짝이 복도 이동선을 침범하지 않게 한다.
- 문이 열린 상태에서도 최소 `1.2m`를 확보한다.
- 계단·구름다리 방화문 앞에는 대기 공간을 둔다.
- 문이 NPC나 플레이어를 밀지 않게 감지 영역을 둔다.
- 문 앞에 캐릭터가 있으면 닫힘을 연기한다.

## 9-3. 가구 충돌

- 책상+의자는 하나의 단순 Box Collision으로 처리한다.
- 의자 다리, 책상 다리, 화분 잎에는 개별 충돌을 만들지 않는다.
- 고정 가구에 RigidBody를 사용하지 않는다.
- 통과할 수 있을 것처럼 보이는 `0.4~0.8m` 틈을 만들지 않는다.
- 통과 가능 구간은 최소 `0.9m`.
- 통과 불가능 구간은 벽 또는 단일 충돌로 완전히 막는다.
- 의자는 기본적으로 밀리지 않는 고정 오브젝트로 사용한다.

# 11. NPC 규모

문서상 학교는 약 500명 규모지만 모두를 동시에 실시간 렌더링하지 않는다.

## 활성 NPC 권장 수

- 일반 층: `10~20명`
- 급식실·운동장·강당: `20~35명`
- 멀리 있는 학생:
  - 저해상도 모델
  - 애니메이션 프록시
  - 창문 실루엣
  - 그림자
  - 발소리·대화 음향
  - 비활성 처리

## 이동 규칙

- 교실 NPC는 책상 사이를 무작위 순찰하지 않는다.
- 지정 좌석에서 일어나 가장 가까운 주통로로 이동한다.
- 복도는 좌우 흐름을 나누거나 로컬 회피를 사용한다.
- 계단에는 한 방향 우선권을 둔다.
- 급식실 좌석 NPC는 테이블 사이 모든 틈을 경로로 사용하지 않는다.
- 관람석 NPC는 지정된 계단 통로만 사용한다.
